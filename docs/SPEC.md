# ヘアサロン公式LINE システム仕様書

最終更新: 2026-07-25

## 1. 概要・ゴール

LINE公式アカウント1つで、ヘアサロンの集客・予約・接客・販売までを完結させる。

- **ゴール**：LINEひとつでマーケティングが完結する状態を作る
- **開発方針**：現段階はポートフォリオとして無料枠のみで構築し、実案件化する際に必要な有料プラン（後述）を導入する
- **開発の進め方**：一番規模の大きい「予約システム」を土台として最初に作り、そのあとに他の機能を少しずつ追加していく

## 2. 機能一覧とフェーズ構成

| フェーズ | 機能 | 状態 |
|---|---|---|
| 1 | 予約システム（LIFF専用アプリ） | 実装中 |
| 2 | 予約前日リマインド（Cronでの自動プッシュ） | 未着手 |
| 3 | 事前ヒアリング（希望の髪型を予約時に聞く） | 未着手 |
| 4 | よくある質問Bot | 未着手 |
| 5 | サロン紹介LIFF（HP代わり） | 未着手 |
| 6 | ポイントカード機能 | 未着手 |
| 7 | リッチメニューの出し分け（予約状況等に応じて表示切替） | 未着手 |
| 8 | サロン商品購入（LIFF＋決済） | 未着手 |

### 各機能の実現方式（メモ）
- **予約**：外部予約サービスには頼らず、LIFF専用アプリを自前で開発する（確定事項）
- **よくある質問**：リッチメニュー or キーワード応答Bot（Flex Message＋postbackパターンを流用）
- **事前ヒアリング**：LIFFの問診フォーム（画像アップロード対応も検討可）
- **サロン紹介**：静的なLIFFページ
- **商品購入**：LIFF＋Stripe決済。実質簡易ECを構築する
- **前日リマインド**：Vercel Cron Jobsが毎日、翌日予約のお客様を予約DBから抽出してPush Message送信
- **ポイントカード**：来店実績（予約DB）を土台にスタンプ・ポイントを付与
- **リッチメニュー出し分け**：予約済み/未予約などのお客様の状態に応じて表示を変える

## 3. リッチメニュー・あいさつメッセージ設計

- **あいさつメッセージ**：友だち追加時に、テキストの挨拶＋「今すぐ予約する」ボタン（LIFFの予約画面を直接開くURIアクション）を送信
- **リッチメニュー**：2タブ構成
  - タブ「予約」：予約に特化した大きい導線
  - タブ「メニュー」：よくある質問／サロン紹介／商品購入／ポイントカードなどのアイコンを配置

## 4. システム構成（技術スタック）

```
[お客様のLINEアプリ]
      │
      ├─ リッチメニュー / あいさつメッセージのボタン → LIFF（LINEアプリ内Webページ）が開く
      │
      └─ トークでメッセージ送信 → Webhook（サーバーの受け口）
            → 内容に応じて自動応答・予約確定通知など

[サーバー: Vercel（Next.js）]
      ├─ Webhook（/api/line/webhook）：LINEからのイベントを受信
      ├─ LIFFページ（/liff/xxx）：予約フォーム・サロン紹介などのWeb画面
      ├─ DB（Neon Postgres, Prisma ORM）：顧客・予約・メニュー・スタッフ情報を保存
      └─ Cron（定期実行）：前日リマインドなどのバッチ処理
```

| レイヤ | 技術 | 備考 |
|---|---|---|
| フロント／API | Next.js（App Router, TypeScript） | Vercelにデプロイ |
| LIFF | @line/liff | LINEアプリ内WebView |
| Messaging API | @line/bot-sdk | Webhook受信・メッセージ送信 |
| DB | Neon Postgres + Prisma | 無料枠で開始 |
| 決済（フェーズ8） | Stripe | 初期費用なし、決済ごとに手数料 |
| ホスティング | Vercel | Hobbyプラン（無料）で開始 |

## 5. DB設計（現状）

`prisma/schema.prisma` に実装済み。

- **Customer**：LINEの友だち＝予約者。`lineUserId`で1対1に紐づく
- **Staff**：スタイリスト。`weeklyOffDay`で定休日を表現
- **Service**：施術メニュー。`durationMinutes`（所要時間）と`price`を保持
- **Reservation**：予約本体。`customer` / `staff` / `service`への参照、`startAt` / `endAt`、`status`（CONFIRMED / CANCELED / COMPLETED）、`requestNote`（要望メモ、フェーズ3で拡張予定）、`reminderSentAt`（フェーズ2の前日リマインドで使用）を保持

営業時間は現時点ではDBではなく`src/lib/business-hours.ts`に定数で定義（デフォルト: 10:00〜19:00、30分刻み。仮置きで後から変更可能）。

## 7. 予算試算

### LINE公式アカウント
- **無料（コミュニケーションプラン）**：月200通まで。開発・ポートフォリオ段階はこれで運用
- **ライトプラン：月5,000円（月5,000通）**：実案件化した際の目安プラン。応答メッセージ（Botの自動返信）は通数にカウントされず、予約確認・前日リマインド・クーポン配信などの「こちらから送るPush Message」のみカウント対象
  - 試算：来店100人/月 × リマインド1通＋予約確認1通 = 200通、＋月1回150人へのクーポン配信 = 150通 → 合計 **月350通程度**。顧客数500〜1,000人規模のサロンでもライトプランで十分な想定
- 2026年10月にLINEの追加メッセージ料金改定が予定されているが、ライトプラン以下は影響を受けない

### インフラ
| 項目 | サービス | 費用目安 |
|---|---|---|
| Webhook / LIFFホスティング | Vercel | Hobbyプランで無料（個人〜小規模） |
| DB | Neon Postgres | 無料枠で開始可 |
| 決済（フェーズ8） | Stripe | 初期費用0円、決済ごとに約3.6% |
| 独自ドメイン | 任意 | 年1,500円程度（LIFFのみなら必須ではない） |

→ **開発・ポートフォリオ段階は実質0円。実案件化する際はLINEのライトプラン月5,000円が主な固定費。**

## 8. 開発環境に関する注意事項

作業ディレクトリを`ポートフォリオ１　ヘアサロン`（日本語・スペース入り）ではなく、`~/Desktop/hair-salon-line-app`（英数字名）に分けて開発している。理由：`create-next-app`などNode系CLIツールは日本語・スペース入りのディレクトリ名でスキャフォールドに失敗するため。
